# reSpeaker XVF3800 firmware (LiveKit ESP32 client)

The XVF3800 hardware is a two-chip system:

- **XMOS XU316** — 4-mic array processing: acoustic echo cancellation, noise
  suppression, beamforming. It hands the ESP32 a clean, full-duplex audio
  stream (I2S). Stock DSP firmware works as-is; see Seeed's
  [XVF3800 wiki](https://wiki.seeedstudio.com/respeaker_xvf3800_introduction/)
  if you ever need to reflash it.
- **XIAO ESP32-S3** — runs the network stack. Seeed's stock firmware targets
  **Agora/TEN framework** and cannot talk to LiveKit, so we flash our own
  firmware built on the official
  [livekit/client-sdk-esp32](https://github.com/livekit/client-sdk-esp32) SDK
  (developer preview, distributed via the Espressif Component Registry;
  ESP-IDF ≥ 5.4; ESP32-S3, bidirectional Opus audio with AEC on the XMOS).

The SDK's examples (`voice_agent`, `minimal`, `minimal_video`) live under
`components/livekit/examples/` in the repository; start from
**`voice_agent`** (bidirectional voice chat with an AI agent). The XVF3800 is
not in the example's built-in board list — a custom codec-board entry is
covered in §3.1 below.

> The LiveKit ESP32 SDK docs are the source of truth for configuration keys —
> the exact Kconfig symbol names below may differ slightly per release.

## 1. Install ESP-IDF (≥ 5.4)

Follow https://docs.espressif.com/projects/esp-idf/en/v5.4/esp32s3/get-started/
(Linux: `install.sh esp32s3`, then `. ./export.sh`).

## 2. Create the voice-agent firmware project

The SDK is distributed through the Espressif Component Registry — cloning the
SDK repo is optional. Run this **outside this repository** (it creates a
`voice_agent/` project directory) with the ESP-IDF environment active:

```bash
idf.py create-project-from-example "livekit/livekit=0.3.2:voice_agent"
cd voice_agent
idf.py set-target esp32s3
```

> The SDK is in developer preview and its layout has changed before: the
> examples now live under `components/livekit/examples/` in the repository
> (the old top-level `examples/voice_agent` path no longer exists). To browse
> or patch SDK sources, clone the repo and work from that path; the registry
> version above is pinned, so builds stay reproducible.

(Connect the XIAO ESP32-S3 to the XVF3800 carrier board first; the XIAO must
be mounted on the reSpeaker board so it can reach the XMOS over I2S.)

## 3. Configure

Configure via the **"LiveKit Example"** menu (`idf.py menuconfig`) or by
editing `sdkconfig` directly. For this stack:

```ini
# WiFi
CONFIG_LK_EXAMPLE_USE_WIFI=y
CONFIG_LK_EXAMPLE_WIFI_SSID="<your SSID>"
CONFIG_LK_EXAMPLE_WIFI_PASSWORD="<your password>"
# Talk to OUR LiveKit server (not the LiveKit Cloud sandbox)
CONFIG_LK_EXAMPLE_USE_PREGENERATED=y
CONFIG_LK_EXAMPLE_SERVER_URL="ws://<host-LAN-IP>:7880"
CONFIG_LK_EXAMPLE_TOKEN="<output of the mint command below>"
# Custom XVF3800 board entry added in §3.1
CONFIG_LK_EXAMPLE_CODEC_BOARD_TYPE="XVF3800"
```

> The example also offers a LiveKit Cloud sandbox mode
> (`CONFIG_LK_EXAMPLE_USE_SANDBOX`) with its own hosted demo agent — ignore
> it. This stack provides the agent; the example's bundled `agent/` folder is
> not needed. Tokens expire — mint a long-lived one for the device (below).

### 3.1 XVF3800 codec-board entry (required once per project)

The example plays/captures audio through Espressif's `codec_board` component,
which only knows a fixed list of dev boards — the XVF3800 is not among them.
Add a custom entry to
`managed_components/tempotian__codec_board/board_cfg.txt` (the directory is
created on the first build; re-apply the edit if you ever delete
`managed_components`):

```
Board: XVF3800
i2c: {sda: 5, scl: 6}
i2s: {mclk: 9, bclk: 8, ws: 7, din: 43, dout: 44}
out: {codec: DUMMY, use_mclk: 1}
in: {codec: DUMMY}
```

Pins per the XVF3800 schematic / Seeed's ESPHome guide: the XMOS XVF3800
handles mics, AEC and the TLV320AIC3104 speaker codec; the ESP32-S3 only
exchanges 2-channel I2S audio with it (WS = GPIO7, BCLK = GPIO8,
MCLK = GPIO9, DIN = GPIO43, DOUT = GPIO44) and reaches it over I2C
(SDA = GPIO5, SCL = GPIO6). With the stock XMOS firmware the ESP32 is the
I2S master and provides MCLK. `DUMMY` codec means the ESP32 configures no
codec chip itself — if the speaker stays silent, the AIC3104 needs explicit
I2C setup per Seeed's wiki.

Mint the device token from the server host:

```bash
cd /opt/src/voice-assistant
docker compose run --rm agent python /app/scripts/mint_token.py \
    --identity respeaker-1 --room home --name "reSpeaker" \
    --ws-url ws://<host-LAN-IP>:7880 --valid-hours 8760
# paste the JWT into menuconfig (or into the token source file, per example docs)
```

Tip: long-lived token (`--valid-hours 8760`) for the device; treat it like a
password. Room `home` is the default conversation room.

## 4. Build & flash

```bash
idf.py build
# put the XIAO ESP32-S3 into bootloader if needed (hold BOOT, tap RESET),
# find its serial port (often /dev/ttyACM0), then:
idf.py -p /dev/ttyACM0 flash monitor
```

You should see it join WiFi and connect to the LiveKit room; the agent joins
automatically and speaks the greeting through the XVF3800's speaker output.

## 5. Verify & iterate

- Server side: `docker compose logs -f agent` shows `joining room home`.
- Talk: *"what time is it?"*, *"set a 5 minute timer"* — full-duplex works
  (you can interrupt the agent; the XMOS AEC cancels its echo).
- The agent also publishes data messages (topic `assistant.event`, e.g. timer
  expiry) which the firmware can use for LEDs/UI — see
  `client-sdk-esp32` data-stream APIs.

## 6. Wake word overlay (ESP-SR WakeNet, connected standby)

The firmware can be extended with an Echo-style on-device wake word using the
overlay in this repository (`firmware/`): the device stays in the LiveKit room,
but publishes only silence until the wake word is heard. Full behavior, tuning
and troubleshooting: **`firmware/README.md`**.

Apply it after §2/§3 (ESP-IDF environment active):

```bash
cd voice_agent
cp -r /opt/src/voice-assistant/firmware/main/. main/
cp /opt/src/voice-assistant/firmware/partitions.csv .
cat /opt/src/voice-assistant/firmware/sdkconfig.defaults.wakeword >> sdkconfig.defaults
rm -f sdkconfig && idf.py set-target esp32s3 && idf.py menuconfig
```

Wake-word specifics on top of §3:

- **Flash size**: the overlay switches the project to 8 MB and adds an esp-sr
  `model` partition (`firmware/partitions.csv`) - required for `srmodels.bin`.
- **Wake word model**: menuconfig → *ESP Speech Recognition → Load Multiple
  Wake Words* (default `wn9_hilexin`, "Hi Lexin"; alternatives include
  `wn9_hiesp` "Hi ESP", `wn9_alexa`). Keep exactly one model enabled.
- **Behavior menu**: menuconfig → *Wake Word* (enable gate, pre-wake buffer,
  follow-up window, detection threshold, chime).
- **Build & flash**: `idf.py build && idf.py -p /dev/ttyACM0 flash monitor` -
  esp-sr's build automatically adds `build/srmodels/srmodels.bin` to the flash
  step.
- **Verify**: on boot, `wake_word: WakeNet 'wn9_hilexin' ready: phrase
  "Hi Lexin"` then `wake_word: Gating armed`; say the wake phrase → chime +
  `wake_word: Wake word detected (...), going active`; after ~10 s of quiet →
  `re-arming`. While armed the agent receives no audible audio.
- The XIAO ESP32-S3's 8 MB PSRAM holds the model and the pre-wake buffer; the
  SDK's `show_threads()` (see the SDK README) plus `docker compose logs -f
  agent` on the server side are the quickest health checks.

Stock models are English/Chinese; custom phrases (e.g. German) need
Espressif's WakeNet customization service, a microWakeWord model, or LiveKit's
[`livekit-wakeword`](https://github.com/livekit/livekit-wakeword) models once
they run on ESP32 (the engine interface `firmware/main/wake_word_engine.h` is
swappable). See `firmware/README.md` and `docs/architecture.md`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Connect fails w/ 401 | token room/identity mismatch, or `LIVEKIT_API_SECRET` changed after minting |
| Connect fails w/ timeout | server unreachable: check `ws://` host IP, firewall (TCP 7880, UDP 50000-50200) |
| No audio captured | check the XVF3800 board entry in §3.1 (I2S pins per Seeed's schematic) and that the XMOS runs its stock I2S-capable DSP firmware |
| Echo of the agent's own voice | ensure the XMOS AEC path is used (don't bypass the XVF3800 DSP) |
| Random disconnects when a participant leaves | known SDK issue in the 0.3.x developer preview (see the SDK README) — update the component version |
